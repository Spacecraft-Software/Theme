# AGENTS.md

## What this repo is

A multi-platform theme distribution for the Spacecraft Software brand. Since
the palette-family release (2026-09-23) it is a **generated** tree: one source
(`Steelbore/steelbore.toml`, the canonical Steelbore Standard §11 contract) and
one generator (`tools/steelbore_themes`, plain Python ≥ 3.11, zero
dependencies) render every registered theme into every platform's native
format. Each top-level category directory targets a class of host environment
(JSON for VSCode/Zed, XML+`.theme.json` for JetBrains, `.colors` for KDE,
`.ron` for COSMIC, GTK CSS for GNOME/XFCE/MATE, TOML for Lapce/Starship/Zamak,
KDL for Niri, `.conf` for Hyprland, manifests for browser extensions,
`.reg`/`.theme` for Windows, ANSI colour scripts for shells/terminals, …).

**Never hand-edit a generated file.** Generated files carry a provenance header
(`GENERATED by tools/steelbore_themes …`) or live under a `themes/` directory.
Change the renderer in `tools/steelbore_themes/renderers/<platform>.py` and
regenerate. `tools/README.md` is the renderer contract — read it before
touching a renderer.

```sh
cd tools
python3 -m steelbore_themes generate        # render every target
python3 -m steelbore_themes validate        # re-render, compare with disk, exit 1 on drift
python3 -m steelbore_themes package         # rebuild every shippable archive
python3 -m steelbore_themes registry        # rewrite Steelbore/steelbore.json
```

`validate` is the test surface: it fails on any hex outside the theme's own
palette, any lifted colour outside a high-contrast variant, any pre-generator
legacy colour, unparsable JSON/TOML/XML, CRLF, or a file that differs from what
the generator would write.

Most platform folders ship **both** the generated source tree (`themes/`) and a
pre-built archive (`.zip` / `.tar.gz` / `.xpi` / `.vsix`). Archives are
deliverables rebuilt by `package` — treat them as stale until rebuilt, and
rebuild them in the same commit as a renderer change.

**Aspirational README references** — `README.md` documents several artifacts
that don't yet exist in the tree. Don't try to invoke or locate them; treat them
as a backlog:
- `Scripts/install-spacecraft-software.sh` (and the whole `Scripts/` directory)
- Per-shell installers it sources
- The Microsoft Office VBA macro (`Spacecraft-Software-Office-Theme.bas`) — there is no `Office/` category folder either

`Themes.md` at the repo root points to the published VSCode / Antigravity
marketplace listings. Those URLs still use the pre-rename `SteelBore` publisher
namespace — fix when the listings are re-published under `Spacecraft-Software`.

## The palette family (§11)

The single source of colour is `Steelbore/steelbore.toml` — copied verbatim
from the `steelbore-color-palette` skill (`assets/steelbore.toml`), currently
palette family **v3.5.0** for Standard **v2.08**. To update: copy the new TOML
over it, run `generate`, `registry`, `package`, and review the diff. Never
retype a hex; never add a colour that is not in the TOML.

Thirteen palettes, twenty-five themes, every one rendered for every target:

| Slug | Palette | Status |
|------|---------|--------|
| `steelbore` (+`-high-contrast`) | Steelbore Modern | **default**, listed first everywhere |
| `steelbore-blue`, `-magnetar`, `-biolume`, `-navywhite`, `tokyonight`, `-hanzosteel`, `-blackpinkpanther`, `-green`, `-greenalt` (each +`-high-contrast`) | nine alternates (§11.3) | opt-in |
| `steelbore-classic` (+`-high-contrast`) | the pre-v1.34 Void Navy / Molten Amber palette | legacy six-role contract (§11.2); this repository's original look |
| `solarized-dark`, `solarized-light` | Solarized, verbatim | **fidelity palettes (§11.5) — non-conforming**, shipped for interoperability only; no high-contrast sibling |
| `steelbore-mono` | 4-bit ANSI names | palette-independent; only targets that take ANSI names (shells, Starship, TTY) emit it |

`steelbore-navywhite` and `solarized-light` are the only light canvases; every
renderer sets its platform's dark/light flag from the theme, never by hand.

**Role tokens** (§11.1): `background`, `surface`, `surface-alt`, `foreground`,
`accent`, `structure`, `success`, `error`, `warning`, `focus`, `border`.
Renderers map platform keys onto these meanings only (the table in
`tools/README.md`). Invariants the validator and reviewers enforce:

- Surface tokens are fills, never text (§11.0.1). "Muted / disabled /
  placeholder" text takes `structure`.
- Text on a fill is only ever a foreground role on a canvas/surface, or the
  canvas on an accent fill — both verified pairs. Foreground-on-foreground is
  not verified and is not emitted.
- Steelbore Blue's accent (Electric Blue) is large-text/non-text only;
  `theme.text_safe_accent` substitutes `structure` in normal-size text slots.
- Lifted (`* Lift`) colours belong to the high-contrast variant only.
- Translucent fills are `theme.with_alpha(role, "40")` — palette hex + alpha.
- **ANSI 16 derivation** is fixed in `core.py` and never re-derived: black =
  background, red = error, green = success, yellow = warning, blue = structure,
  magenta = accent (text-safe), cyan = focus, white = foreground; bright 8–15
  equal 0–7 except bright-black = structure. The old Dracula-derived bright set
  (`#FF6E6E`, `#69FF94`, …) and the invented `#050530` / `#6272A4` / `#E6E6F0` /
  `#FE6B00` / `#0E141D` colours are gone; the validator rejects them.
- Fonts (§12): Inconsolata (body/mono), Share Tech Mono (headings), `monospace`
  fallback. No JetBrains Mono, Consolas, Outfit, Roboto.

The former "known exceptions" (a CLI-tuned `#0E141D` variant for Claude Code,
a `#FE6B00` browser accent) no longer exist — those targets render the family
like everything else.

## Adding a new theme target

1. Create `<Category>/<TargetName>/` (Editors, Terminals, Desktops, Shells, Browsers, CLIs, AI, or Bootloaders) with a hand-written `INSTALL.md` (header line `**Version:** 2.0 | **Author:** Mohamed Hammad | **License:** GPL-3.0-or-later | **Website:** [SpacecraftSoftware.org](https://SpacecraftSoftware.org)`).
2. Add `tools/steelbore_themes/renderers/<target>.py` following `kitty.py` and the contract in `tools/README.md`. Declare `legacy_files` (none for a new target) and `archives` if the platform consumes one.
3. `cd tools && python3 -m steelbore_themes generate --target <id> && python3 -m steelbore_themes package --target <id>`.
4. Add the target to the relevant section of `README.md`.

## Contribution rules (from CONTRIBUTING.md) — enforce these on every change

- **License**: GPLv3+. Every new source file gets the two-tag SPDX header (`SPDX-FileCopyrightText` + `SPDX-License-Identifier`) in the appropriate comment syntax; JSON and binaries are covered by `REUSE.toml`.
- **POSIX shell only**: Shell scripts must run under `sh`/`dash`. No bashisms. The exception is per-shell modules under `Shells/<ShellName>/`, which target that specific shell.
- **Python** (the generator): `mypy --strict` clean, `ruff` clean (`tools/pyproject.toml`), stdlib only, every function typed, frozen `slots` dataclasses.
- **Dates**: ISO 8601 (`YYYY-MM-DD`, `HH:MM:SS`, UTC `Z`). Metric units only.
- **Privacy-Friendly App rules**: No telemetry, analytics, ads, tracking, or remote calls in any script or extension. Local storage only. No third-party subresources (§9.1).
- **Accessibility**: every conforming palette ships its `-high-contrast` sibling; targets that take ANSI names ship `steelbore-mono` for `NO_COLOR`.
- **Keybindings**: Anything with shortcuts must support both CUA and Vim-style navigation.

## Editing conventions

- The Anthropic `.skill` files in `AI/Claude/` are zip archives of the sibling directory of the same name; that directory is a copy of the skill's canonical source under `/spacecraft-software/construct/<skill>/` (or the installed `~/.claude/skills/<skill>/` when construct lags). Sync the directory, then rezip.
- Image assets (`background.png`, `icon.png`, `Spacecraft_Software_wallpaper_blue.png`) are duplicated across `Desktops/*/` and `Browsers/*/` folders by design and are not archived with the themes.
- `Desktops/Windows/Spacecraft-Software.themepack` is a Windows cabinet built by hand on Windows from the Classic-era `.theme`; it cannot be regenerated here and is stale until rebuilt on Windows.
- The repo is large (pre-built archives and PNG assets). `git push` over SSH for a fresh clone takes several minutes; budget for that.
- **Upstream-preset adaptation pattern**: when a target already has a high-quality community preset (Starship's catppuccin-powerline, oh-my-posh, p10k), port the preset verbatim into the renderer as a template and substitute only its named palette with role tokens. `renderers/starship.py` is the reference: it keeps the preset's format string and every module table and rewrites `[palettes.<slug>]` per theme.
